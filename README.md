# Таро Манара — офлайн-разбор

Приложение для разбора раскладов на Таро Манара с акцентом на сочетания карт. Есть два явно выбираемых режима: локальный ИИ в браузере устройства (по умолчанию) и серверный ИИ. Автоматического перехода в облако нет.

## iPhone: установка на экран «Домой»

Это PWA — сайт, устанавливаемый на главный экран через Safari. Не нужны Ollama, Mac, Apple Developer или еженедельная переподпись. ZIP содержит исходники, а не файл `.ipa`: сначала сайт нужно один раз собрать и разместить на HTTPS.

1. Загрузите **содержимое всего репозитория**, включая `.github`, в GitHub.
2. В настройках репозитория откройте Pages и выберите источник **GitHub Actions**.
3. В Actions выберите **Publish Manara iPhone PWA → Run workflow**. Это отдельное ручное действие публикует статический сайт; само скачивание ZIP ничего не публикует.
4. Откройте адрес опубликованного сайта в Safari на iPhone, выберите «Поделиться → На экран Домой», затем запускайте приложение с этого значка.
5. Дождитесь отметки о сохранении приложения и 78 изображений. В режиме «На устройстве» выберите модель и подтвердите её загрузку по Wi-Fi: примерно 1 ГБ для Qwen 1.5B или 2 ГБ для Qwen 3B. Загрузка может быть больше из-за служебных файлов. Для каждого режима нет скрытого облачного запасного варианта.
6. После запуска модели отключите сеть и выполните пробный разбор. Только успешно завершённая генерация без сети устанавливает отметку «Разбор без сети проверен».

Поддержка WebGPU/shader-f16 проверяется при открытии. Наличие iOS 26 или iPhone 15 Pro Max **не гарантирует** устойчивость модели: нужны свободная память, хранилище и проверка на реальном устройстве. Маленькая модель может существенно уступать большой в русском языке, глубине и связности сочетаний. Qwen 3B требует больше памяти; при ошибке GPU или памяти попробуйте 1.5B. Держите приложение на переднем плане, иначе iOS может остановить вычисления. Приватный режим не подходит.

Приложение, файлы модели и факт реально выполненного офлайн-разбора — три разных статуса. Safari может очистить хранилище: тогда файлы нужно скачать повторно. Полный вопрос, все карты и самостоятельные ракурсы авторов передаются без обрезания; токенизатор модели проверяет размер контекста перед генерацией. Если всё не помещается либо модель не завершает JSON, выводится ошибка, а не неполный разбор. Вопрос и карты остаются в открытой форме; после закрытия/перезагрузки страницы они не сохраняются.

### Если запуск мигает и возвращается к началу

В обновлённой панели есть надпись **«Запуск модели · версия 2»**. После подтверждения скачивания показываются текущий этап и прошедшее время. Пока библиотека не сообщила процент, индикатор неопределённый: это не выдуманный процент скачанных весов.

Выбор модели и последняя техническая стадия сохраняются между перезапусками. Если предыдущая операция не отметила завершение, приложение показывает предупреждение и не начинает скачивание автоматически. Это не устанавливает причину: приложение могло быть закрыто, выгружено системой или перезапущено по другой причине. При полной перезагрузке вопросы и карты не восстанавливаются, поскольку не записываются на диск.

Для снижения начального расхода памяти модель стартует с окном 8192 токена вместо 32768. Перед разбором реальный токенизатор считает весь запрос с источниками и резервом ответа; при необходимости окно расширяется до 16384 или 32768. Источники, карты и вопрос не сокращаются. Большой расклад по-прежнему может превысить возможности памяти iPhone — меньшее начальное окно этого не гарантирует. Временный дополнительный токенизатор уничтожается перед расширением памяти, а не остаётся загруженным со старта.

Техническая запись содержит только идентификатор модели, этап, состояние, время и размер окна контекста — без вопроса, выбранных карт, ответа или сырых сообщений провайдера. Параллельная загрузка в другой вкладке может выглядеть как незавершённая предыдущая операция; не запускайте несколько копий модели одновременно.

### Обновление уже опубликованного приложения

1. В GitHub Desktop сначала нажмите **Fetch origin**, затем **Pull origin**, если эта кнопка появится. Это важно, если файл публикации уже исправлялся через сайт GitHub.
2. Откройте папку репозитория и скопируйте в неё содержимое архива исправления `manara-iphone-startup-fix.zip`, согласившись заменить перечисленные файлы. Не удаляйте `.git` и не создавайте дополнительную вложенную папку.
3. Сделайте **Commit**, затем **Push origin**.
4. На GitHub запустите **новый** workflow **Publish Manara iPhone PWA** из ветки `main`. Повтор старого запуска использует старый исходный код.
5. После успешной публикации на iPhone полностью закройте установленное приложение и вкладки этого сайта в Safari, затем откройте приложение с главного экрана. Если старая версия успела скачать обновление и ждёт закрытия, может потребоваться ещё одно полное закрытие и открытие. Не очищайте данные сайта: это удаляет сохранённые файлы моделей.
6. Проверьте надпись **«Запуск модели · версия 2»**. В этой и следующих версиях есть кнопки проверки и установки обновления. Установка требует подтверждения перезагрузки с предупреждением об очистке открытой формы; во время загрузки модели или генерации она недоступна.

В режиме устройства приложение не вызывает браузерное распознавание речи, которое может использовать облако. Для строгой автономности вводите вопрос текстом. Серверный режим включается отдельно и отправляет вопрос выбранному API; статический GitHub Pages не предоставляет серверный API, поэтому там используйте режим устройства.

### Нужна ли сборка на Windows?

Для описанного варианта — нет: GitHub Actions собирает сайт автоматически после ручного запуска workflow. На Windows не нужно устанавливать Node.js, Ollama или инструменты Apple. Готовый статический сайт после сборки находится в `artifacts/manara-reading/dist/public`. Для GitHub Pages вида «имя репозитория в адресе» путь `BASE_PATH` должен совпадать с ним; workflow вычисляет его автоматически.

Каталог и политика разбора экспортируются при каждой сборке из единой серверной базы командой `sync:offline`. Сгенерированный `src/generated/manara-core.js` не содержит сервер, облачные ключи или полные OCR-книги. Проверка экспорта: `pnpm --filter @workspace/manara-reading run verify:offline`.

## Что умеет приложение

- Вводить вопрос текстом или диктовать его на русском языке.
- Выбирать пол вопрошающего, глубину разбора и от 1 до 12 карт.
- Добавлять карты вручную в нужном порядке или вытягивать выбранное число случайных карт без повторов.
- Получать общую тему расклада, трактовку каждой карты в контексте вопроса, анализ связей, осторожный ответ, альтернативы и вопросы для саморефлексии.
- Показывать все 78 изображений из локальной папки `artifacts/manara-reading/public/cards`.
- Создавать разбор на модели WebLLM непосредственно в браузере без сервера либо, при явном выборе, использовать сервер.

## Дополнительный серверный вариант: Ollama на компьютере

Нужны Node.js 20+, pnpm и установленная Ollama. Веса модели в репозитории не хранятся: загрузите их один раз, пока есть интернет, затем отключите сеть.

Для `qwen2.5:7b` рекомендуется 16 ГБ оперативной памяти. На слабом компьютере можно выбрать меньшую модель через `OLLAMA_MODEL`, но глубина русского разбора может снизиться. Первый ответ после запуска может занимать несколько минут.

```bash
pnpm install
ollama pull qwen2.5:7b
```

Запустите Ollama (если она не запущена как фоновая служба):

```bash
ollama serve
```

В первом терминале запустите API:

```bash
PORT=8080 MANARA_AI_PROVIDER=ollama OLLAMA_MODEL=qwen2.5:7b pnpm --filter @workspace/api-server run dev
```

Во втором терминале запустите интерфейс:

```bash
PORT=5173 BASE_PATH=/ pnpm --filter @workspace/manara-reading run dev
```

Откройте `localhost:5173`. Картинки, база карт и запросы к модели работают локально. После первичной загрузки модели интернет не нужен. Если используется другой локальный адрес Ollama, задайте `OLLAMA_BASE_URL`.

Голосовая диктовка использует поддержку браузера и может обращаться к его речевому сервису; для строгого офлайн-режима вводите вопрос текстом. Аудио приложение не сохраняет и не отправляет.

## Запуск в Replit

В интерфейсе по умолчанию выбран режим устройства. Если явно выбрать сервер, API в Replit использует Replit AI Integrations; локально API по умолчанию использует Ollama. Проверку реального iPhone или качества мобильной модели нельзя заменить предпросмотром Replit. Команда `dev` запускает собранный PWA-просмотр, чтобы проверить service worker; для разработки с HMR есть `dev:hot`, где полная офлайн-установка не проверяется.

## Состав репозитория

Это pnpm-workspace: `artifacts/manara-reading` — интерфейс и локальные изображения, `artifacts/api-server` — каталог и API разбора, `lib/api-spec`, `lib/api-client-react`, `lib/api-zod` — контракт API и сгенерированные типы.

Не переносите только папку приложения: для запуска нужны общие библиотеки из всего репозитория.

## Проверки разработки

```bash
pnpm install
pnpm run typecheck
```

При изменении `lib/api-spec/openapi.yaml` обновляйте типы:

```bash
pnpm --filter @workspace/api-spec run codegen
```

## Ограничения трактовок

Карты используются как символический материал для размышления, а не как способ достоверно узнать мысли и чувства другого человека, поставить диагноз или гарантировать будущее. В репозитории сохранены краткие оригинальные заметки по 78 картам, синтез мастей и числовых значений, а также 165 коротких дополнений по обработанным сканам и DjVu. Источник и страницы привязаны к каждому дополнению; расхождения авторов сохранены. Проверка базы: `pnpm --filter @workspace/api-server run verify:knowledge`. Подробности и ограничения источников — в `KNOWLEDGE_SOURCES.md`.

## Авторские права

В публичный архив включены 78 изображений, как было запрошено. Загруженные книги в репозиторий не включены; заметки по картам написаны кратко и своими словами, без копирования книжного текста. Веса моделей не включены: браузерные модели скачиваются после подтверждения пользователя с Hugging Face, служебная библиотека — из реестра WebLLM. Ollama скачивает свои модели отдельно. Лицензии выбранных моделей действуют независимо от кода приложения.
